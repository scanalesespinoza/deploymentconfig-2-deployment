# Security Policy

## Reporting a Vulnerability

If you discover a security vulnerability in this project, please follow these steps:

1. **Do not disclose the issue publicly** (do not open a public issue or discuss it in public channels).
2. Send an email to **sergio.canales.e@gmail.com** with:
   - Subject: `[SECURITY] Brief description of the issue`
   - Details:
     - Complete description of the vulnerability.
     - Steps to reproduce.
     - Potential impact (what an attacker could do).
     - Affected environments (Kubernetes/OpenShift versions, OS, etc.).
   - Attach logs, screenshots, or a proof of concept if available.

3. The maintainers will:
   - Acknowledge receipt within **48 hours**.
   - Provide a status update within **7 business days**.
   - Propose a fix or workaround within **15 business days**, or as soon as feasible depending on the severity.

## Responsible Disclosure

- Once a fix is released and a secure version is published, you may publicly disclose the vulnerability.
- We appreciate your help in keeping the project safe and secure.

## Affected Versions

- List versions that are known to be vulnerable (e.g., `v1.2.0`, `v1.2.1-beta`, etc.).
- If the issue has not been released yet, indicate “Not applicable (in development)”.
